# Contributing to Value-First Development

*[Português abaixo](#contribuindo-com-o-value-first-development)*

Thank you for your interest. Value-First is a young framework, and the most useful contributions are honest ones.

## What helps most

- **Real-world experience.** Did you try a Value Spec, the readiness check or a value check? What worked, and what didn't? Open an issue. With your permission, we'll publish it with a source.
- **Critiques.** Unclear wording, weak arguments, missing credit to prior work, or claims without a source.
- **Templates and examples.** Variations of the Value Spec for specific contexts, such as regulated industries, data products or platform teams.
- **Translations.** PT and EN are maintained together. Other languages are welcome if a native speaker can maintain them.

## Ground rules for content

1. **Every factual claim needs a verifiable source.** Use a link, or a book with chapter. Opinions are fine when they're labeled as opinions.
2. **Invite, don't accuse.** Credit what came before (Waterfall, Agile, Scrum, Kanban, Shape Up). Write about "what we learned and where we can go", not about who failed.
3. **No AI hype.** State limits and risks next to benefits.
4. **Keep PT and EN in sync.** A change in one language should have a matching change in the other in the same pull request, or an issue asking for it.
5. **Short beats complete.** The README should be readable in about three minutes. Depth goes in `docs/`.

## How to contribute

1. Fork the repository and create a branch: `git checkout -b my-change`.
2. Make your change. Use the [Value Spec template](templates/en/value-spec.md) style for new templates.
3. Open a pull request describing **what** changed and **why**.

For larger changes, such as a new principle or practice, open an issue first so we can discuss it.

## Repository layout

```
README.md / README.pt-BR.md   Overview (EN / PT)
docs/en, docs/pt              Documentation (same file names in both)
templates/en, templates/pt    Value Spec, example, agent snippet

```

# Contribuindo com o Value-First Development

Obrigado pelo interesse. O Value-First é um framework jovem, e as contribuições mais úteis são as honestas.

## O que mais ajuda

- **Experiência real.** Você testou uma Value Spec, a checagem de prontidão ou uma verificação de valor? O que funcionou e o que não funcionou? Abra uma issue. Com a sua permissão, publicamos com a fonte.
- **Críticas.** Texto confuso, argumento fraco, falta de crédito a trabalhos anteriores ou afirmação sem fonte.
- **Templates e exemplos.** Variações da Value Spec para contextos específicos, como setores regulados, produtos de dados ou times de plataforma.
- **Traduções.** PT e EN são mantidos juntos. Outros idiomas são bem-vindos se houver um falante nativo para mantê-los.

## Regras para o conteúdo

1. **Toda afirmação factual precisa de fonte verificável.** Use um link, ou um livro com o capítulo. Opiniões são bem-vindas quando aparecem como opinião.
2. **Convide, não acuse.** Reconheça o que veio antes (Waterfall, Agile, Scrum, Kanban, Shape Up). Escreva sobre "o que aprendemos e para onde podemos ir", não sobre quem falhou.
3. **Sem hype de IA.** Coloque limites e riscos ao lado dos benefícios.
4. **PT e EN sincronizados.** Uma mudança em um idioma deve vir com a mudança correspondente no outro, no mesmo pull request, ou com uma issue pedindo isso.
5. **Curto é melhor que completo.** O README deve ser lido em uns três minutos. A profundidade fica em `docs/`.

## Como contribuir

1. Faça um fork do repositório e crie uma branch: `git checkout -b minha-mudanca`.
2. Faça a sua mudança. Para templates novos, siga o estilo do [template de Value Spec](templates/pt/value-spec.md).
3. Abra um pull request explicando **o que** mudou e **por quê**.

Para mudanças maiores, como um princípio ou uma prática nova, abra uma issue antes para conversarmos.
