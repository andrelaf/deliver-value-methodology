# FAQ

### What is Value-First Development, in one sentence?
A light layer on top of the way you already work. It makes the value of each piece of work explicit, shared and measurable before anyone builds it, so people and coding agents build the right thing. See [Why Value-First](./why.md).

### Does it replace Scrum or Kanban?
No. It keeps your cadence, events and board. Value Specs improve what goes into a sprint or a column, and the value check looks at what comes out. See [comparison](./comparison.md).

### Is it only for teams using AI?
No. Every principle works without agents. Agents make the need more visible, because they execute what's written and can't fill gaps the way a colleague does.

### Isn't this just writing more documents?
It shouldn't be. A Value Spec fits on about one page, covers one item of value and lives next to the code. If it grows past a couple of pages, split it. The aim is to learn sooner what's worth building and write down only that. See the waterfall critique in [Specs in the AI era](./ai-and-specs.md#limits-and-risks).

### Who writes the Value Spec?
The Value Pair: Product and the Tech Lead, together. The team reviews it. See [roles](./roles-and-artifacts.md).

### Our Tech Lead already does this. What changes?
The work becomes visible, planned and shared. Product co-owns it, so it no longer depends on one person's memory and evenings.

### What happened to the Value Analyst from v1?
It's no longer a job title, because a third role between Product and Tech adds a handoff, and handoffs lose context. Value analysis remains a skill anyone can bring. See [roles](./roles-and-artifacts.md#what-happened-to-the-value-analyst).

### Does every ticket need a Value Spec?
No. Only items with real uncertainty about value or feasibility, or items built mainly by agents. Bug fixes and routine work don't need one. See [when not to use it](./adoption.md#when-not-to-use-it).

### What if we can't measure the value?
Start with one observable signal you can agree on, even a rough one: support tickets, a step in a funnel, time spent on a task. If nothing can be observed, make that the first open question.

### How do we use it with Spec Kit, Kiro or similar tools?
A Value Spec can be the input for Spec Kit's `specify` step or Kiro's requirements phase. Its constraints can feed a Spec Kit constitution, steering files or AGENTS.md. Value-First decides *what and why*. The tools handle *spec → code*.

### Does it work in regulated environments?
Yes. Compliance requirements go into the "Constraints" section and stay fixed. The decisions log and change log give you an audit trail.

### Is there evidence that it works?
Not yet as outcome data for Value-First itself. The framework rests on published research (DORA, Agile and product literature, listed in [sources](./sources.md)) and on practice. If you adopt it, we'd like to hear what happened: [CONTRIBUTING](../../CONTRIBUTING.md).

### Can I use and adapt it?
Yes. It's MIT-licensed. Take what helps and tell us what you changed.
